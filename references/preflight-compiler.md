# Preflight Compiler｜前置校验与编译

在生成最终 Prompt 之前执行。目标不是增加输出篇幅，而是尽可能在生成前消除会直接破坏结果的冲突，并把用户的自然语言需求规范化为可编译的导演约束。

默认使用 **Silent Preflight**：内部完成校验与必要修正，不向用户展示检查过程。

只有当用户要求“分析、诊断、检查、为什么生成失败、导演模式”时，才使用 **Visible Preflight** 输出关键风险。

---

## 1. Preflight 的职责

Preflight 同时承担三种职责：

1. **Validator**：发现明确冲突、缺失映射和高风险组合。
2. **Normalizer**：把模糊表达规范化为人物、素材、时间、镜头、动作和声音约束。
3. **Compiler**：把已确认的信息转成适合小云雀 Seedance 2.0 / 2.5 的 Prompt 结构。

不要把 Preflight 变成机械问卷。能从上下文可靠推断的内容直接推断；只有缺失信息会改变人物身份、素材顺序、核心剧情或生成模式时才需要追问。

---

## 2. 校验顺序

固定按以下顺序检查，前面的结果可以影响后面的编译：

1. Model Routing
2. Task Mode
3. Asset Map
4. Character Count & Identity
5. Duration & Timeline
6. Camera & Composition
7. Motion & Physics
8. Continuity & State
9. Audio & Dialogue
10. Negative Constraints
11. Prompt Density

---

## 3. 风险等级

### P0｜致命冲突

会导致 Prompt 自相矛盾、无法按要求执行或大概率生成错误结果。必须在输出最终 Prompt 前消除。

典型情况：

- 用户要求固定 5 人，但人物映射实际列出 6 人。
- 总时长 6 秒，时间轴却延伸到 8 秒。
- 同一动作同时要求左手和右手执行。
- 同一时间既要求固定机位，又要求明显环绕主体。
- 同一道具在连续镜头中同时处于互斥状态。
- 同一参考素材被赋予互相冲突且未隔离的职责。

处理方式：

- 优先依据用户最新且最明确的约束消除冲突。
- 如果无法可靠判断哪一个约束优先，导演模式中指出冲突；快速/标准模式下采用最保守且最接近用户核心目标的版本。

### P1｜高风险

不一定失败，但容易导致人物复制、参考污染、时序漂移、动作失真或声音错误。默认自动补强。

典型情况：

- 多张人物图没有逐一映射角色。
- 场景参考图包含人物，但没有明确“不参考人物”。
- 动作参考视频同时包含不同人物或强烈场景风格，但未限制迁移范围。
- 精确人数与“一群人、很多人、学生们”等模糊群体词并存。
- 多镜头存在身份、服装、道具或左右位置连续性风险。
- 递物、摘取、坐下、落地等动作缺少接触或交接阶段。
- 多人对白没有明确说话顺序或未说话人物控制。

处理方式：

- 自动增加必要映射、边界、连续性或动作链。
- 不把修正扩展成大量负向提示。

### P2｜优化项

主要影响质感、清晰度或执行效率，不应为了“完美”强行增加 Prompt 复杂度。

典型情况：

- 运镜稍复杂但仍可执行。
- 单段描述略密但没有明确冲突。
- 光线描述存在重复。
- 不必要的形容词或负向提示较多。

处理方式：

- 只有在不会损害用户原意、不会显著增加 Prompt 长度时才优化。

## 4. Model Routing

先判断使用 Seedance 2.0 还是 2.5。

### Seedance 2.0

倾向：
- 5–15 秒短片
- 少量图片参考
- 简单剧情 / 广告 / 氛围 / 蒙太奇
- 允许模型参与镜头规划

结构可使用：自由叙事型、镜头编号型、时间轴型。

### Seedance 2.5

倾向：
- 多图片 / 视频 / 音频参考
- 多角色、多场景、复杂剧情
- 秒级时间轴
- 参考视频、故事板、白模、视频编辑、片段重拍、视频延长

默认优先连续时间轴。

如果用户明确指定模型，不擅自改模型；只在导演模式下提示明显不匹配风险。

## 5. Asset Map Preflight

每个参考素材至少需要内部解析为：

- `asset_id`
- `primary_role`
- `reference_attributes`
- `must_not_transfer`

例如：

`@图片1：主角外观参考；参考脸型、五官、发型、服装和体型；不参考背景。`

`@图片2：场景参考；参考空间、构图、植物状态和光影；不参考其中人物。`

`@视频1：动作参考；参考动作轨迹、动作速度与镜头节奏；不参考人物外观、服装和场景。`

### 校验

- 每个素材是否有主要职责？
- 是否存在一个素材承担过多互相干扰的职责？
- 是否存在必须禁止迁移的属性？
- 多人物参考图是否与具体角色一一绑定？
- 同一角色多张视角图是否已声明属于同一角色？
- 视频 / 音频参考是否把动作、镜头、音色、节奏等职责拆清？

默认优先“一素材一主要职责”，必要时允许多个次要职责，但必须明确边界。

---

## 6. Character Count & Identity Preflight

建立内部角色清单：

`角色ID → 身份 → 参考素材 → 外观 → 位置 → 当前状态`

检查：

- 精确人数是否前后一致。
- 是否同时出现精确人数和模糊群体表达。
- 同一人物是否被重复描述成两个实例。
- 多镜头中人物是否可能被重新实例化。
- 背景是否可能再次生成相同人物。
- 角色参考是否错误继承了场景图中的人物。

需要严格人数时，优先使用：

`画面中总共只有 6 人：1 位教授 + 5 位学生，不增加其他人物，不复制任何角色。`

不要在同一 Prompt 后面再次使用可能扩大人数的“一群学生、更多学生、人群”等表达。

---

## 7. Duration & Timeline Preflight

### 总时长

所有时间段之和必须覆盖目标时长，不超出、不留无意空档。

### 2.0

仅在时序重要时使用时间轴；简单动作不要为了形式切成过多时间段。

### 2.5

时间轴必须连续：

`0–3s → 3–7s → 7–15s`

避免：

`0–3s → 5–7s`

### 动作密度

单段只承载一个主要剧情任务或一个连贯动作链。

出现以下情况时标记 P1/P2：

- 2 秒内同时要求角色走位、拿物、转身、对白、复杂运镜和转场。
- 一个时间段内出现多个互不相关的主要动作。
- 转场前动作尚未完成，下一镜已要求新的状态。

---

## 8. Camera & Composition Preflight

检查镜头指令是否互相兼容。

高风险组合包括：

- 固定机位 + 明显推进 / 横移 / 环绕
- 严格正视 + 大幅环绕主体
- 高机位俯视 + 同时要求低机位仰拍
- 慢速稳定镜头 + 快速甩镜但没有明确转场节点
- 同一时段同时推进、后拉和环绕

如果用户同时给出“参考图构图必须一致”和复杂运镜：

优先锁定起始机位、视角、主体位置与空间关系，再限制运镜幅度，避免构图漂移。

---

## 9. Motion & Physics Preflight

每个关键动作解析为：

`主体 → 身体部位 / 接触点 → 方向 → 动作链 → 结果 → 局部物理反馈`

检查：

- 动作主体是否明确。
- 左右手是否一致。
- 起点与终点是否存在。
- 接触动作是否包含接触阶段。
- 递物是否包含双方短暂共同承托。
- 落地 / 落枝 / 坐下是否有合理局部受力反馈。
- 是否把局部受力错误扩大成整体场景运动。

典型编译：

`喜鹊落在细枝上 → 接触瞬间枝头轻微下压 → 附近小范围枝条短暂颤动并回弹 → 整棵树保持稳定。`

---

## 10. Continuity & State Preflight

建立关键状态：

- 人物身份
- 服装与体型
- 左右位置
- 左右手
- 道具归属
- 道具颜色 / 大小 / 完整状态
- 人物姿态
- 场景时间与光线
- 声音延续状态

多镜头时检查：

`上一镜结束状态 == 下一镜开始状态`

如果通过遮挡、切镜、转场改变状态，必须有明确触发点或剧情理由。

---

## 11. Audio & Dialogue Preflight

将声音拆成：

1. BGM
2. 环境音
3. 动作拟音
4. 对白 / VO
5. 字幕

检查：

- 用户是否明确要 / 不要 BGM。
- 自动配乐是否会与真实环境音目标冲突。
- 每句对白是否有明确角色。
- 多人对白顺序是否清楚。
- 未说话人物是否可能同步张嘴。
- 音色参考是否绑定正确人物。
- 字幕是否被误当成对白要求。

声音优先绑定画面事件：

`动作发生 → 声音发生 → 动作结束 → 声音收束`

---

## 12. Negative Constraints Preflight

负向约束只用于底线，不用于重复描述正向内容。

常见必要底线：

- 不增加额外人物
- 不复制角色
- 不改变人物身份与服装
- 不穿模、不瞬移
- 未说话人物不要同步张嘴
- 不出现文字 / 字幕 / Logo / 水印
- 不自动生成额外对白
- 无 BGM，只保留指定环境音和动作音（仅用户明确需要时）

如果同一禁止项已经通过明确正向结构解决，不必重复多次。

---

## 13. Prompt Density Check

检查 Prompt 是否出现“控制堆叠”。

高风险表现：

- 同一镜头同时出现多个独立运镜。
- 每个微动作都规定秒点，导致动作链被切碎。
- 大量摄影形容词与剧情动作混在同一句中。
- 同一参考素材重复声明多次。
- 负向词数量超过真正需要控制的核心问题。

处理原则：

优先保留：

`身份 / 数量 / 参考职责 / 核心动作 / 时序 / 构图 / 连续性 / 声音`

其次保留：

`质感 / 光线 / 风格 / 次要环境动态`

---

## 14. Silent Preflight

默认模式。

内部完成：

`解析 → 风险分级 → P0消除 → P1补强 → P2择优 → 编译 Prompt`

用户通常只看到最终 Prompt，不展示 PASS / WARNING / FAIL。

---

## 15. Visible Preflight

仅在用户明确要求分析或诊断时显示。

推荐简洁格式：

```text
Preflight
- 模型路由：PASS
- 素材职责：WARNING — 场景图包含人物，需限制人物迁移
- 人物数量：PASS — 固定 6 人
- 时间轴：PASS
- 镜头：FAIL — 固定机位与环绕镜头冲突
- 动作物理：PASS
- 连续性：WARNING — 柿子归属在转场后未明确
- 声音：PASS
```

然后输出：

`问题 → 原因 → 修改策略 → 最终 Prompt`

不要输出无意义的全部 PASS 项；优先展示 P0、P1 和真正影响结果的 P2。

---

## 16. 与 Postflight 的分工

### Preflight

生成前发现输入层和结构层问题。

### Prompt Compiler

把通过校验的信息编译成适合 2.0 / 2.5 的最终提示词。

### Postflight / Prompt 审核器

生成后再次检查最终文本是否在编译过程中重新引入：

- 人数冲突
- 素材职责污染
- 时间轴断裂
- 运镜冲突
- 左右手 / 道具状态冲突
- 声音矛盾
- 不必要负向堆叠

最终工作流：

`User Brief → Preflight → Prompt Compiler → Postflight → Final Prompt`

---

## 17. 原则边界

- Preflight 是静态风险检查，不保证模型 100% 执行。
- 不把经验性风险写成官方硬限制。
- 小云雀平台行为、Seedance 模型能力、工程经验三者必须区分。
- 用户提供新的官方资料或可复现工程案例时，优先更新规则。
